# 2bee.app — Functional Specification

Every feature is numbered, has **acceptance criteria that a machine can check**,
and names the check that proves it. A feature is not "done" when the code exists;
it is done when its check has been **seen going red** on a planted defect and then
green on the fix.

Status legend: ✅ done and covered · 🟡 partial, and the gap is named · 🔴 not
covered, and the gap is named

## The Gate column is machine-checked — gate `SPEC`

**Every token in the Gate column must resolve to something that exists**, and
`gates/slicer_gate_check.mjs` (gate **SPEC**) fails if one does not. The grammar
is three forms plus an escape hatch, each in backticks and separated by ` · `:

| Form | Means | Resolved against |
|---|---|---|
| `G3`, `P7`, `TECH`, `K3`, … | a gate in the gate runner | the `GATES` table in `gates/slicer_gate_check.mjs` |
| `core:some_test_fn` | a Rust `#[test]`, run by gate **G0** | `fn some_test_fn(` under `core/src/**.rs` |
| `e2e:"a test title"` | a Playwright test, run by gate **I1** | `test('a test title'` in `web/e2e/*.ts` |
| `none` | **nothing covers this row** | nothing — and SPEC counts these and prints the count |

`none` is not a loophole, it is the point: **an uncovered row that says so is
honest, and a green nobody can back is the defect this column was rewritten to
remove.** SPEC prints the uncovered count on every run so it cannot grow quietly.

## Third pass, 2026-08-09 — **does the citation cover the CLAIM?**

The two passes above asked *"does this token resolve?"*, and `SPEC` now enforces
that mechanically. This pass asked the question `SPEC` explicitly **cannot**
ask, and says so at the bottom of its own section in `SLICER-GATES.md`:

> ⚠ **What SPEC does NOT check: that the cited check actually covers the row.**
> It proves the citation resolves to a real, runnable thing — not that the thing
> asserts the acceptance. A resolving citation is a floor, not a coverage claim.

🔴 **That is the dangerous residue of the 33-dangling-id defect, not its
leftovers.** A dangling id is *loud*: a reader looks it up, finds nothing, and
knows. A citation that **resolves to a real green check which asserts something
else** is silent — it survives `SPEC`, it survives the eye, and it is a green
that means *unchecked*. All 111 citations were opened and read against the
acceptance beside them.

**Result: 98 covered · 10 miscovering · 0 dangling · 3 `none`.** The ten are
listed in the rows below and each one says what it did and did not assert. Six
were repaired by citing a check that **already existed and had never been
named** — the coverage was real and the spec was pointing at the wrong thing —
and four leave a limb that genuinely nothing asserts, so those rows lost their
✅ (`A5`, `F2`, `G-5`, `G-12`).

⚠ **No row gained a `none` in this pass, and that is a claim about the evidence,
not a target.** Every one of the ten had at least one limb genuinely covered, so
blanking the cell would have *deleted* real evidence to make a tidier number.
The uncovered count stays at 3 because coverage did not move — only the accuracy
of the pointers did. **A citation was never removed to make a row look worse,
and never added to make one look better.**

**The pattern, because it recurred and will recur.** Eight of the ten cite a
**gate**, and a gate's negative control is what fixes its scope: `G7` drives
`--no-arcs`, so it can only ever speak for `PostOptions::emit_arcs`; `G3`'s
plant shifts the *part*, so it can only ever speak for the limit check; `P9`
counts *gouges*, so it is blind to material left standing. **Read the plant, not
the gate's name** — the name is written to describe the feature, the plant is
what decides the claim.

⚠ **A4's gate arrived DURING this audit, and the record of that is left visible
on purpose.** A gate `PROBE` (XYZ touch plate) appeared in the runner mid-write
and first reported **PENDING — *"the core did not produce the probe dump (cargo
exit 101)"***. It was not cited then: a citation to a gate that has never
executed is exactly the defect the `SPEC` grammar exists to prevent, one level
up. Fifteen minutes later it passed, and `A4` now cites it. **The rule that
survives is the sequence, not the outcome — cite a gate after you have watched it
run, never because it exists in the table.**

## Scope

**Subtractive CNC is what is BUILT** — founder 2026-08-08, *"CNC only for now"*
plus *"design the tool for later FDM."*

The second half is a design constraint, not a feature: a second process must be
able to arrive as a new file rather than as an edit to the CNC path. That is
carried by `core/src/tech.rs` (the `Technology` enum every process-specific
question is asked through), `core/src/post.rs` (dialects selected BY technology,
with `None` rather than a fallback), and per-technology banned-word lists that
live in the core so the ban never has to be emptied to make room. Gate **TECH**
holds all three, and the seam is exercised by a second post implemented inside a
test rather than merely asserted.

No FDM slicing exists — OrcaSlicer keeps the X2D. No PCB isolation milling or
autorouting (founder, same week). See `README.md` for the full statement of what
is designed for versus what is built.
